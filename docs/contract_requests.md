# Contract change requests

Agents never edit `contracts/` directly. Append a request here; the owner decides and bumps the schema version.

Every open row was answered by owner decision D25 (2026-10-30, `docs/RFC.md` "Owner decisions") when
`docs/design/capability-policy.md` was approved: contracts v1.3 (`DetectorResult.role` "observe";
`ClassifyResponse.policy_id`, `policy_version`, `bundle_sha256`, `unscored_by_any_step`, `escalation_reason`) plus
the two new contracts `CapabilityManifest` 2.0 and `ExecutionPolicy` 1.0. Several requests were answered by moving
the field out of the manifest and into the policy rather than by adding it to `ArtifactManifest`, which is now
read-only (accepted, converted, never written).

| 2026-10-30 | Agent B | `ArtifactManifest` | Make "Stage 1 may finalize allow only" explicit, e.g. `stage1_finalizes: ["allow"]` or `["allow", "flag"]` (default both), instead of encoding it as `gray_zone = [low, 1.0]` | `stage1-tfidf-v2.1` is published with `gray_zone [0.505068, 1.0]` because the milestone allows Stage 1 to finalize only allow (`training/CASCADE.md`). Today nothing in the contract says which comparison is used | **Resolved by D25, `ExecutionPolicy` `Band.finalize`:** `finalize: {"allow"}` says allow-only and `flag_at_or_above` is set iff `"flag"` is in it. The comparison operators are fixed by the schema (cleared iff `score < clear_below`, flag iff `score >= flag_at_or_above`), and the band lives in the policy, not in the manifest, so a routing change is a policy version and not a model version. |

| 2026-10-30 | Agent A (serving) | `ClassifyResponse` / `DetectorResult.role` | Define how an observe-only stage appears on the wire.
